# MCACS 轻量生存服反作弊调查系统开发计划

## 1. 产品目标

MCACS 面向通常同时在线 3–10 人的小型 Minecraft 生存服务器。管理员可能长时间不在线，因此系统必须在无人值守时持续监测和保存证据，在管理员回来后提供高质量、低噪声的调查入口。

产品定位：

> 通过轻量检测和 3D 世界回放帮助管理员理解异常行为，而不是依赖黑盒式自动封禁。

核心原则：

1. 低误报优先：优先保证交给管理员的案件具有较高可信度。
2. 管理员最终裁决：永久封禁和长期处罚默认需要管理员确认。
3. 自动措施可逆：无人值守时只允许警告、临时踢出或短期重连冷却。
4. 产品体验占比高、运行资源占比低：3D 前端是主要调查空间，但不参与检测决策，未打开时不产生持续渲染开销。
5. 所有处罚可解释、可回放、可审计。

## 2. 目标用户与默认场景

- 服务器类型：生存服为主，兼顾少量 PvP。
- 在线规模：3–10 人。
- 部署方式：单机 Node.js 服务、Paper/Spigot 插件、SQLite/JSONL 本地存储。
- 管理方式：管理员不保证实时在线，主要通过离线摘要和案件复核管理。
- 优先检测：X-Ray、Fly、Speed、Scaffold，其次为 Reach、KillAura、AutoClicker。

## 3. 产品决策

### 3.1 权威处理链路

```text
原始游戏事件
→ 检测信号
→ 风险与可信度聚合
→ InvestigationCase 调查案件
→ 管理员复核或可逆软处置
→ 指令执行
→ ACK 后提交处罚结果
```

WarningTracker 只提供重复违规上下文，不再直接执行长期封禁。VP 表示调查优先级，不再等同于处罚积分。VerificationGate 决定处罚建议是否成立，不能在验证通过前产生“处罚已执行”的状态。

### 3.2 默认处置策略

| 风险 | 默认行为 | 是否需要管理员 |
|---|---|---|
| 低 | 静默记录并衰减 | 否 |
| 中 | 创建或更新案件 | 事后查看 |
| 高 | 高亮 NPC、加入待审核列表 | 是 |
| 极高 | 强化观察；后续版本可配置临时踢出 | 是 |
| 已确认 | 管理员选择警告、踢出、临时或永久封禁 | 是 |

默认关闭自动长期处罚。任何自动踢出策略必须同时满足高威胁、高可信度、至少两个独立检测器或物理不可能证据，并设置有限冷却时间。

## 4. 核心数据模型

### 4.1 检测信号

每个检测器输出观察事实，不直接宣称玩家作弊：

```ts
interface InvestigationSignal {
  id: string
  cheatType: CheatType
  confidence: Confidence
  evidence: Evidence[]
  timestamp: number
  repeatOffense: boolean
}
```

### 4.2 调查案件

同一玩家的中高可信信号聚合为一个案件。案件包含风险分数、可信度、涉及检测器、关键证据、管理员判断与审计时间。

### 4.3 回放事件

后续版本采用有限时间窗口保存语义事件：玩家位置、视角、方块破坏/放置、攻击、检测信号与豁免条件。平时使用内存环形缓冲区，只有案件成立时才写入本地存储。

## 5. 3D 调查体验

3D 城镇是主要工作空间，不是装饰层：

- 玩家 NPC 表示实时或历史玩家。
- 待审核案件通过 NPC 图标、光效和调查台入口呈现。
- 管理中心显示管理员离线期间摘要。
- 矿区承载 X-Ray 地下轨迹与隐藏矿脉关系回放。
- 调查实验室承载 Fly/Speed 合法轨迹对比和 Scaffold 放置回放。
- 档案馆保存历史案件和管理员裁决。
- 裁决室提供确认、驳回、继续观察和处罚操作。

所有动画必须可跳过；案件列表、筛选和快捷操作始终可用。

## 6. 分阶段开发计划

### Phase 1：案件闭环基础

任务：

- [x] 建立 `InvestigationCaseManager` 和轻量 JSON 持久化。
- [x] 聚合同一玩家的中高置信检测信号。
- [x] 将重复违规作为风险证据，不再直接自动封禁。
- [x] 默认关闭自动处罚，保留管理员手动处罚能力。
- [x] 提供案件查询、统计和复核 API。
- [x] WebSocket 广播案件开启、更新和解决事件。
- [x] 3D 场景中为涉案 NPC 显示调查标记。
- [x] 增加案件调查台，支持聚焦 NPC、确认、驳回和继续观察。

验收：

- 中高置信检测会创建或更新唯一的玩家案件。
- 普通检测 ACK 不会确认处罚。
- 管理员可以在页面中查看并复核案件。
- 驳回案件后 NPC 调查标记消失。
- 重启后案件仍可查询。
- 后端测试、后端构建和前端生产构建通过。

### Phase 2：离线摘要与案件质量指标

任务：

- [x] 记录管理员最后查看时间。
- [x] 生成离线期间在线峰值、案件数量、自动措施、TPS 最低值摘要。
- [x] 增加案件确认率、驳回率、平均处理时间和各检测器确认率。
- [x] 合并重复告警，控制每名玩家同时只有一个活跃案件。
- [x] 增加案件保留策略：中风险 7 天，高风险 30 天。

验收：管理员打开页面后可在 30 秒内了解离线期间是否发生重要事件。

### Phase 3：证据环形缓冲区与时间轴

任务：

- [x] 每名玩家保存最近 20 秒语义事件。
- [x] 普通移动每 3 Tick 采样一次，调查期间逐 Tick 采样。
- [x] 案件成立时冻结前后关键窗口并持久化。
- [x] 前端实现可暂停、拖动和变速的统一回放时间轴。
- [x] 显示 TPS、Ping、状态效果和已应用豁免。

验收：单个案件证据默认控制在 100 KB 内，回放不依赖实时连接。

### Phase 4：X-Ray 地下调查场景

任务：

- [x] 保存玩家附近有限范围的挖掘路径和矿石上下文。
- [x] 标记矿石是否暴露、玩家变向节点和隐藏矿脉方向。
- [x] 计算高价值矿物命中效率、最短路径偏差和跨样本异常度。
- [x] 在矿区场景中显示轨迹、矿脉和检测信号。
- [x] 支持正常分支挖矿与疑似追矿的并排解释。

验收：管理员无需阅读原始日志即可理解 X-Ray 案件的主要证据。

### Phase 5：Fly、Speed 与 Scaffold 回放

任务：

- [x] 建立 TPS、Ping、状态效果、载具、击退和传送归一化模型。
- [x] 同时显示实际轨迹与合法物理预测范围。
- [x] 为 Scaffold 显示视线、放置面、间隔和移动路径。
- [x] 将合法豁免以独立颜色显示，避免隐藏系统的不确定性。

验收：管理员能准确区分“超出物理范围”和“因环境条件获得豁免”。

### Phase 6：无人值守软处置

任务：

- [x] 引入威胁分与可信度双分数。
- [x] 仅在双高且证据独立时启用临时踢出。
- [x] 首次冷却 10 分钟，重复触发延长至 30 分钟。
- [x] Java 端按 `actionId` 实现幂等执行缓存。
- [x] 区分 queued、delivered、executed 三种动作状态。

验收：无人值守措施全部可恢复，不会自动产生永久封禁。

### Phase 7：性能与部署完善

任务：

- [x] Headless 与 Dashboard 模式解耦。
- [x] 地下回放、档案馆、音频和后处理动态加载。
- [x] 提供阴影、粒子、后处理和采样质量档位。
- [x] 建立 `survival`、`pvp`、`mixed` 三套策略预设。
- [x] 增加案件回放回归样本和干净服务器误报测试集。

验收：无浏览器连接时后端资源占用接近纯检测模式；前端首包不继续无界增长。

## 7. 质量指标

- 高风险案件管理员确认率目标：大于 90%。
- 误报率按检测器、Ping 和 TPS 区间统计。
- 案件平均处理时间可观测。
- 自动长期封禁数量默认始终为 0。
- 任何自动措施都能在本地审计日志中解释触发条件。
- 每阶段必须通过单元测试、TypeScript 构建和前端生产构建。

## 8. 明确不做

- 不引入 Redis、Kafka 或外部数据库。
- 不在当前阶段引入机器学习训练服务。
- 不保存完整网络包或整个 Minecraft 世界。
- 不让 3D 前端参与权威检测和处罚决策。
- 不为追求检测数量牺牲误报率与可解释性。
